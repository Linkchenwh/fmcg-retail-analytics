# 数据模型与执行契约

## 粒度

| 对象 | 粒度 | 约束 |
|---|---|---|
| 原始交易 | 一篮中的商品记录行 | 不能直接以商品ID作为交易主键 |
| 商品维度 | 商品ID | 范围状态include/exclude/pending与展示组保留 |
| 家庭维度 | 家庭ID | 人口属性缺失不排除家庭 |
| 购物篮 | 不同篮ID | 家庭、相对日及门店应在篮内一致 |
| 客户快照 | 家庭×分析窗口 | 多窗口不能相加计算家庭数 |
| 活动分配 | 家庭×活动 | 类型汇总的分母不是不同家庭数 |
| 券资格 | 家庭×活动×券 | 重复核销事件不能重复计资格对 |
| 陈列/邮报上下文 | 商品×门店×相对周 | 先归并复合键冲突再关联交易 |

正式结构见sql/03_build_model.sql。经营和客户分析执行器要求已有fact、dim、mart三个schema，并具备该SQL定义的表、视图和列。执行器不会创建或替换正式数据库。

## 建模SQL的前置输入

审计查询依赖raw源表/类型视图。模型SQL依赖只读附加的audit.raw源以及scope_input临时映射；映射须经过商品完整路径范围复核。公开代码不包含自动生成全部映射的驱动和源数据，不应以空映射或全量纳入来绕过前置条件。

金额使用固定小数；异常保留标记。家庭人口属性从家庭底表左连接，避免只剩具有人口属性的子样本。优惠券商品桥与核销事件不直接连接到交易金额汇总，避免多对多扩行。

## Power BI关系

07_powerbi_export.sql准备显式类型的导入表，DAX源码与其列名一致。模型采用维度到事实的单向一对多关系，不通过双向过滤硬连交易、快照及券事实。客户快照窗口独立选择，交易商品/周切片器不会重新计算固定快照。
